# Storavix — обновление сервера Linux через CLI

**Для уже установленной службы Storavix на Linux с systemd.** Не требуется искать `scripts/update-linux.sh` в старой копии исходников, заходить в `~/Storavix` или вручную скачивать ZIP. Система и пользователь администратора сохраняются.

## Первое обновление (одна команда)

В терминале любого каталога выполните:

```bash
bash -o pipefail -c 'curl -fsSL https://raw.githubusercontent.com/iPapik/Storavix/main/scripts/update-online-linux.sh | sudo bash'
```

`curl` получает сам обновлятор по HTTPS с официального GitHub-репозитория проекта. `sudo bash` запускает его с необходимыми правами, а `pipefail` сообщает об ошибке, если скачивание прервалось. **Важное замечание по безопасности:** выполнение полученного из интернета скрипта с правами root предполагает доверие к содержимому ветки `main`. Администратор может предварительно просмотреть файл по [адресу скрипта](https://github.com/iPapik/Storavix/blob/main/scripts/update-online-linux.sh), а также скачать файл и проверить его перед выполнением.

## Все последующие обновления

После первого успешного обновления достаточно:

```bash
sudo storavix-update
```

Команда `/usr/local/sbin/storavix-update` устанавливается автоматически и при **каждом запуске** скачивает свежий исходный код `main` из `https://github.com/iPapik/Storavix.git`. Скрипт корректно работает **из любой текущей директории** и не использует `/var/lib/storavix` как каталог сборки.

## Что происходит во время обновления

1. Проверка прав, systemd, состояния установки и блокировка повторного запуска.
2. Установка недостающих `git`, `curl`, `python3`, `tar`, `sha256sum` (на Debian/Ubuntu через apt при необходимости).
3. Скачивание исходников в автоматически удаляемую папку `/tmp/storavix-online.*`.
4. Проверка Go 1.23+. При отсутствии/устаревании компилятора — загрузка актуального Go во **временную** папку с официального сайта и проверкой опубликованной SHA256.
5. Компиляция нового сервера и **локального** агента, если тот установлен на этом же хосте. Действующая служба в это время продолжает работать.
6. Создание приватной резервной копии бинарника и настроек в `/var/backups/storavix/backup-*` (права доступа 0700). В момент создания снимка данных службы останавливаются, чтобы файлы не менялись при копировании.
7. Замена только `/usr/local/bin/storavix` и, при наличии, `/usr/local/bin/storavix-agent`. Linux и другие установленные приложения не переустанавливаются.
8. Запуск службы и проверка `GET /api/health` на адресе из `/var/lib/storavix/instance.json` (до 30 секунд), сохранности `state.json` и `master.key`.
9. При неудаче — восстановление предыдущих бинарных файлов и данных из бэкапа, попытка вернуть прежнюю службу. Данные неудачного запуска сохраняются в папке бэкапа для диагностики.

**Внимание:** пока обновление в процессе, сайт может быть недоступен несколько секунд. Чем больше данных накоплено, тем больше времени займёт создание резервной копии. Старые резервные копии не удаляются автоматически, чтобы избежать потери возможности отката: следите за свободным местом.

## Проверка

```bash
sudo systemctl status storavix --no-pager
curl -fsS http://127.0.0.1:8080/api/health
sudo journalctl -u storavix -n 80 --no-pager
sudo ls -lah /var/backups/storavix
```

Если выбран нестандартный адрес/порт, используйте свой адрес из `instance.json` вместо `127.0.0.1:8080`.

## Если команда не выполняется

- `Could not resolve host` / `fatal: unable to access` — проверьте DNS, шлюз, интернет и доступ к `raw.githubusercontent.com`, `github.com`, `go.dev` (Go требуется только если локальный компилятор старый или отсутствует).
- `Служба не установлена` — этот обновлятор предназначен для существующей native-установки с `/etc/systemd/system/storavix.service` и `/usr/local/bin/storavix`.
- `Нет state.json` — обновление остановлено, чтобы не удалить учётную запись. Выполните диагностику текущих данных.
- `No space left on device` — освободите место на диске с каталогом бэкапов; повторите запуск, **не удаляя** каталог `/var/lib/storavix`.
- `HTTP API ...` — автоматический откат и сохранение лога. Посмотрите `sudo journalctl -u storavix -n 100 --no-pager`.
- Docker-контейнер не использует systemd-службу и требует отдельного способа обновления образа (`docker compose pull` / `docker compose up -d --build` в каталоге Compose). Не запускайте этот обновлятор для Docker-инсталляции.

## Windows

Для Windows по-прежнему используется `scripts/update-windows.ps1` из новой версии; **Linux-команда `sudo storavix-update` на Windows не работает**. Автоматическую онлайн-команду Windows и удалённое обновление агентов на других хостах реализуем отдельно. Данные в `C:\ProgramData\Storavix` необходимо сохранять при обновлении.

**Не удаляйте** `/var/lib/storavix`, `master.key`, `state.json` и `agents.json` вручную: они содержат настройки и информацию об устройствах. Бэкапы содержат секреты, поэтому доступ к ним должен быть только у администраторов.
