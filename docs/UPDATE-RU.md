# Storavix — обновление без переустановки

Обновление не требует установки Windows/Linux заново, повторного создания администратора или перенастройки SMTP. Настройки хранятся отдельно от бинарного файла: `/var/lib/storavix` в Linux, `C:\ProgramData\Storavix` в Windows. **Делайте дополнительную внешнюю резервную копию** перед обновлением важной системы.

## Linux

1. Скачайте новый архив/код Storavix из GitHub и распакуйте в новый каталог.
2. Запустите из каталога нового проекта:

```bash
cd ~/Storavix
sudo bash scripts/update-linux.sh
```

Если отсутствует Go и есть новый готовый бинарник:

```bash
sudo env STORAVIX_BINARY="$(pwd)/storavix" bash scripts/update-linux.sh
```

Скрипт: (1) проверит существующую службу; (2) соберёт новую версию или возьмёт готовый бинарник; (3) создаст резервную копию программы и данных под `/var/backups/storavix/`; (4) остановит systemd-службу; (5) заменит исполняемый файл; (6) запустит службу и проверит `http://127.0.0.1:8080/api/health`. При неудачной проверке автоматически восстановит старый бинарник и резервную копию данных, после чего попытается запустить старую версию.

При нестандартном порте 8080 поправьте health URL в скрипте перед запуском. На время обновления будут кратковременные перерывы веб-панели.

## Windows

Откройте PowerShell администратором в распакованном **новом комплекте**:

```powershell
Set-ExecutionPolicy -Scope Process Bypass -Force
cd C:\Storavix
.\scripts\update-windows.ps1
```

При отсутствии Go можно указать новый EXE через `$env:STORAVIX_BINARY`. Скрипт сохраняет бэкап в `%ProgramData%\Storavix-Backups`, останавливает задачу, заменяет бинарник, запускает задачу и проверяет HTTP API. В случае ошибки пытается откатить бинарник и данные.

## Агенты

Для локального обновления агента повторно запустите из нового комплекта `scripts/install-agent-linux.sh` / `scripts/install-agent-windows.ps1` — прежний ID, URL и токен останутся. Агентов на *других* серверах веб-сервер пока не обновляет автоматически.

## Безопасность

Папки бэкапов содержат ключ шифрования SMTP и хэши паролей. Предоставляйте к ним доступ только администраторам. Не загружайте папки `data/`, `.env`, `agent.token`, `master.key` в публичный GitHub.
