# Storavix: порядок выполнения задач

По указанию владельца проекта изменения и исправления должны доводиться до рабочего релиза, а не заканчиваться макетами, рекомендациями или открытым pull request.

- Изучить актуальный код и последний релиз, реализовать изменение, добавить регрессионные тесты.
- Сохранить существующие данные, конфигурацию, совместимость агентов и механизмы обновления.
- Синхронизировать номер версии в VERSION, сервере, telemetry.AgentVersion и установщиках WiX/Inno Setup, обновить русские release notes.
- После проверок объединить изменения в main и запустить штатную публикацию GitHub Actions (коммит с [publish-release] или тег версии).
- Проверить результат CI и наличие опубликованных файлов релиза. Не заявлять об успешной публикации до подтверждения.
- В ответе владельцу предоставить ссылку на релиз, команду обновления и краткий список изменений. При изменениях агента предоставить прямые ссылки на MSI и Setup EXE соответствующего релиза, включая сохранение совместимости Windows Server 2012/R2.
- При блокере сообщить фактический статус; не выдавать незавершённую сборку за готовый релиз.
